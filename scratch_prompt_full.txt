# ANTIGRAVITY — TEMPO COMMUNITY MIGRATION

## Objective

Transform the existing Tempo Post area into **Tempo Community**, integrating the existing Learn & Solve functionality into one unified section with five navigation categories:

1. Announcement
2. Tips (Solve)
3. Learn
4. Posts
5. Direct Message

Use the provided UI screenshots as the primary visual references.

This is a migration of the existing Tempo application, not a new application or a ground-up rebuild.

## 1. Mandatory pre-implementation audit

Before editing any files:

- Inspect the current project structure, routes, page components, navigation, shared UI components, and styling.
- Locate the existing Tempo Post implementation and all Learn & Solve pages and components.
- Inspect existing Supabase tables, queries, authentication, Row Level Security (RLS), storage, and realtime subscriptions where applicable.
- Identify which features are already functional and which are prototypes or mock data.
- Map existing routes, data sources, and dependencies to the five destination categories.
- Identify duplicated components that can safely be shared.
- Review existing user roles and permissions before changing access behavior.

Do not assume table names, schemas, routes, or feature capabilities. Discover them from the existing codebase.

Create a concise implementation plan based on the actual project structure, then proceed with implementation.

## 2. New Community navigation

Rename the existing Tempo Post entry point to **Tempo Community**.

Inside Community, create a consistent left sidebar containing:

- Announcement
- Tips
- Learn
- Posts
- Direct Message

Follow the supplied mockups for the sidebar, active navigation state, content positioning, spacing, typography, borders, card radii, and colors.

Requirements:

- Only one Community entry point should exist in the main navigation.
- Learn & Solve must no longer appear as an independent destination in the primary navigation after migration.
- Existing deep links should continue to work where practical, redirecting to the corresponding Community section when necessary.
- Preserve return-navigation context when users enter Community from another Tempo mode.
- Provide responsive layouts for desktop and mobile.
- Use reusable components and centralized design tokens.

## 3. Announcement

Purpose: official system and product updates.

Implement the announcement listing using the first supplied mockup.

Each announcement may contain:

- Title
- Short description
- Optional cover image or screenshot
- Publication date
- A “See more” action
- An optional “Try it now” action linked to a relevant Tempo feature

Reuse existing announcement content and data sources if present.

Do not turn ordinary user posts into announcements.

Only authorized system administrators should be able to create or edit official announcements. Follow existing authorization patterns and enforce permissions server-side or through appropriate database policies, not merely by hiding UI buttons.

If the current project has no working announcement management backend, document that gap rather than inventing an incompatible schema.

## 4. Tips — migration of Solve

Purpose: practical, actionable solutions for students.

Migrate the existing Solve functionality into the Tips category.

Use the supplied Tips mockup as the visual reference:

- Search bar at the top
- Responsive grid of solution cards
- Clear title
- Short usage description
- “See more” action
- Existing detail or modal behavior, where available

Preserve existing Solve content, categories, detail views, and relevant links.

Do not recreate the content as unrelated static cards if it already exists in the database.

Tips should help users identify an actionable strategy and, where appropriate, navigate to relevant Tempo features.

## 5. Learn — migration of the knowledge library

Purpose: educational resources and explanatory content.

Migrate the existing Learn functionality into Community's Learn category.

Use the supplied Learn mockup as the visual reference:

- Search bar at the top
- Article cards with title, short description, and optional illustration
- “See more” action
- Existing article detail view or modal, where available

Preserve existing article content, images, categories, and links.

Keep Learn distinct from Tips:
- Learn explains concepts and builds understanding.
- Tips provides actionable strategies for solving immediate problems.

Do not merge these content types into an indistinguishable feed.

## 6. Posts — existing Tempo Post functionality

Migrate the current Tempo Post interface into the Posts category.

Use the supplied Posts mockup as the primary reference.

Preserve existing working functionality, including where supported:

- Creating and editing posts
- Viewing post details
- Comments and replies
- Reactions and likes
- Bookmarking
- Search and filters
- User post history
- Notifications
- Image uploads
- User identity and timestamps

Maintain existing community interaction patterns and data relationships.

Do not replace real database functionality with mock data or local-only state.

Avoid introducing duplicate post records, repeated subscriptions, duplicate comments, or repeated list items during migration.

If the existing implementation already supports a feature, preserve it rather than creating a second implementation.

## 7. Direct Message

Preserve the existing Direct Message interface and functionality.

Use the supplied mockup as a visual reference:

- Conversation list on the left
- Active conversation on the right
- Message history
- Message input
- Send action
- Existing unread indicators and conversation metadata where supported

Preserve existing access controls, realtime behavior, and message history.

Do not weaken privacy rules or allow users to read conversations they are not authorized to access.

On mobile, adapt the two-panel layout into a usable conversation-list and conversation-detail navigation flow.

## 8. Data and backend migration

This task primarily changes information architecture and navigation. Do not perform unnecessary database migrations.

Before changing any data structure:

- Identify which existing tables and records serve Learn, Solve, Posts, Announcements, and Direct Messages.
- Reuse existing data sources wherever possible.
- Preserve record IDs, ownership, timestamps, relations, and historical records.
- Avoid copying existing content into new tables unless a documented technical reason requires it.
- If a schema change is necessary, provide a migration plan and safe rollback strategy.
- Preserve RLS policies, user permissions, and storage access controls.
- Verify that existing queries continue to work after route and component changes.

Do not delete Learn & Solve data or tables merely because their standalone page is removed.

## 9. Visual design and accessibility

Use the screenshots as visual guidance, not as a reason to introduce a new design system.

Maintain Tempo's existing brand identity:

- Warm cream backgrounds
- Tempo orange accents
- Existing typography and spacing tokens
- Rounded cards and soft surfaces
- Clear active navigation states
- Readable body text and accessible contrast

Use the project's existing font and design tokens where available.

Ensure loading, empty, error, and success states are designed consistently.

All navigation items, search fields, cards, and buttons must have real behavior. Do not leave decorative controls that appear functional but do nothing.

## 10. Regression and acceptance testing

Verify:

1. Community is accessible through one primary navigation entry.
2. All five categories load the correct content.
3. Learn and Solve content remains accessible after migration.
4. Existing post creation, reactions, comments, bookmarks, and uploads still work where supported.
5. Direct messages and message history remain accessible to authorized users.
6. Announcement permissions are enforced.
7. Search and content-detail interactions work.
8. No duplicate content is introduced by repeated fetching or rendering.
9. Refreshing a page or opening a deep link works correctly.
10. Navigation back to the previous Tempo context works.
11. Desktop and mobile layouts are usable.
12. Supabase queries and RLS continue to behave correctly.
13. Unrelated Tempo modes and functionality remain unchanged.

Run the available tests and production build checks. Fix any regressions introduced by this migration.

Do not claim that an integration or feature works unless it has actually been verified.

## Expected Output

After implementation, provide:

1. A summary of the new Tempo Community architecture.
2. A mapping of the old Learn & Solve and Tempo Post features to the five new categories.
3. A list of modified and newly created files.
4. Any database, storage, or RLS changes.
5. Confirmation of which existing features were preserved.
6. Tests performed and their actual results.
7. Any incomplete functionality or manual steps required before deployment.

Implement the migration in the existing project. Preserve existing data and working features, and do not redesign unrelated parts of Tempo.
