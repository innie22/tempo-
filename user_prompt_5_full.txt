==================================================
1. TEMPO PLANNING MODEL — SOURCE OF TRUTH
==================================================

Tempo planning uses these user inputs:

TASK
What needs to be done?

DEADLINE
When must it be completed?

ESTIMATE
How much focused work does the user expect this task to require?

AVAILABILITY
When can the user work?

EXECUTION ORDER
In what order does the user want to work on tasks?

Tempo converts these inputs into a realistic TIMELINE.

Conceptually:

Tasks
+
Deadlines
+
Focused-work estimates
+
Availability
+
Execution order
+
45/15 work rhythm
+
recovery between completed tasks
=
PLANNED TIMELINE

IMPORTANT:

The generated timeline is an OUTPUT.

It is not immutable user input.

When the user explicitly changes execution order, Tempo should recalculate the affected timeline.

==================================================
2. ESTIMATE MEANS FOCUSED WORK
==================================================

A task estimate represents expected FOCUSED WORK duration.

Example:

Task A
Estimate: 2 hours

This does NOT mean:

"Reserve one continuous 2-hour calendar block."

Instead Tempo may convert 2 hours of focused work into:

45 min focus
15 min break

45 min focus
15 min break

30 min final focus

Total focused work:
120 minutes

The breaks are planning overhead added by Tempo.

Do NOT count break time as task focused-work estimate.

Do NOT silently change the estimate because breaks are added.

==================================================
3. 45 / 15 RHYTHM
==================================================

Use the Tempo default planning rhythm:

45 minutes focused work
15 minutes break

for longer work.

The final focus segment may be shorter.

Example:

Estimate = 1h 30m

45 focus
15 break
45 focus

Example:

Estimate = 2h

45 focus
15 break
45 focus
15 break
30 focus

Do NOT add an unnecessary 15-minute break after the task has already finished.

==================================================
4. RECOVERY BETWEEN COMPLETED TASKS
==================================================

After finishing one task and before beginning the next task, Tempo should provide approximately:

30 minutes recovery

This is distinct from the normal 15-minute within-task break.

Conceptually:

Task A

45 focus
15 break
45 focus

TASK A COMPLETE

30 min recovery

Task B begins

45 focus
...

Avoid stacking:

15-minute within-task break
+
30-minute recovery

after the final focus block of a completed task.

Once the task finishes, transition into the between-task recovery period.

==================================================
5. AVAILABILITY IS A WORK WINDOW
==================================================

Availability means:

"The user CAN work during this period."

It does NOT mean:

"This exact block belongs to one specific task."

Example:

User availability:

6:00 PM – 12:00 AM

Tempo can use that continuous window to arrange:

focus
break
focus
recovery
next task
break
etc.

==================================================
6. NORMALIZE COMPATIBLE AVAILABILITY
==================================================

If availability blocks are contiguous and compatible, treat them as a continuous planning window.

Example:

6:00–8:00
8:00–10:00
10:00–12:00

6:00–12:00

Do NOT duplicate capacity.

If blocks overlap, do not double-count overlapping time.

If there is a genuine gap:

9:00–12:00

do NOT merge across 8:00–9:00.

The user is unavailable during that gap.

Preserve the underlying availability records.

Normalization is for planning calculation only.

23. LATER ≠ UNARRANGED
==================================================

This distinction is CRITICAL.

LATER:

- task is arranged
- task has execution position
- task has scheduled time
- user knows when it is planned
- "LATER" is a presentation label within the arranged plan

UNARRANGED:

- task belongs to Eplan
- task still needs work
- task keeps all task data
- task currently has NO scheduled time
- user has not decided when to do it

Never use LATER as a synonym for Unarranged.
